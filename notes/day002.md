2. The noticeable point/points I discovered from today's git & github practices

   Find the answer for - Why did the pull request show 2 commits after my second push, without you opening a new one ?
   
   1. A pull request tracks a branch (lab/day002-pull-request), not just a single snapshot in time — so when I added a second commit (feat(lab): update file after self review) and ran git push, GitHub automatically updated the open PR to include both commits (268ec64 and 3667d11). That makes it super practical for revising work during a review before merging into main

   2. Merging on GitHub and cleaning up locally are two separate steps that work together — after clicking Merge pull request and Delete branch on GitHub, switching back to main, running git pull, using git branch -d lab/day002-pull-request, and running git fetch --prune kept my local repo clean and synced with origin without leaving stale branches behind.
