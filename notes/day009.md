2. The noticeable point/points I discovered from today's git & github practices

   Find the answer for - After git stash, where is your change: in the working folder, in a commit, or somewhere else?
   1. After running `git stash`, the uncommitted change is neither in the working folder nor in a branch commit—Git stores it separately inside the `.git` directory on a stack (referenced as `stash@{0}`), resetting the working directory back to match the latest `HEAD` commit.

   2. Using `git stash` followed by `git stash pop` keeps the commit history clean during interruptions: I was able to commit the urgent fix (`lab/day009-urgent.txt`) on its own without mixing half-finished edits into that snapshot, and `git stash pop` both restored my draft changes and automatically dropped `stash@{0}` from the stash list.
